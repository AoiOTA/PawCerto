# Stock PhysX reconstruction of the UMI foot sensor input

The implementation estimates solver-only world foot Fz through official PhysX tensor APIs, without an engine patch or second simulated robot. Normal-speed native checks and a complete contact shadow support the calculation, but subsequent high-speed diagnostics exposed both an unsupported gyroscopic branch and a near-zero numerical limitation in the EMD consumer. The gyro term is now corrected; the full high-speed 6D check still has three angular components outside its original tolerance. Small positive force residuals can change the original flying branch, so this is not a demonstrated numerically equivalent replacement for the original sensor. The corrected 4000-iteration learning evaluation completed and exposed unstable MuJoCo transfer; historical normal-contact training remains separately labeled. See the [learning result](umi-reconstructed-learning-result.md).

## Signal and evidence

For the floating-base generalized velocity, the model computes `qdd_free = solve(M, tau_free - C - delta_C - G)` and each link's world CoM acceleration `a_free = J qdd_free + bias`. The bias is reconstructed recursively from actual parent topology and world CoM positions/velocities. The current PhysX acceleration-reporting source combines forward-dynamics acceleration and the solver velocity increment divided by the physics time step. For a leaf foot, the force estimate is `mass * (reported_acceleration - a_free)`, using world Z for EMD.

Forward dynamics scales all DOF velocities in an articulation by `r=min(1,min(vmax/abs(raw_qd)))`, leaving the root twist unchanged. Public C instead uses the asymmetric per-DOF rule `min(raw_qd,+vmax)` and updates public link velocity to that state. The implementation captures the raw DOF velocities and C-conditioned COM velocities, then computes `V_F = V_C + J @ [0, r*raw_qd-min(raw_qd,+vmax)]`. Applying this increment preserves the previous numerical path when no DOF clamp activates.

Let `b_F` and `b_C` be the COM-tree biases for these respective velocities, and `g(omega)=cross(omega,I_world@omega)`. With `s=min(1,1/(dt*norm(omega_F)))`, the DOF/gyro correction, before the additional body-speed term described below, is:

```text
delta_C = sum(J.T @ [m*(b_F.linear-b_C.linear),
                    I_world@(b_F.angular-b_C.angular)
                    + g(s*omega_F)-g(omega_C)])
qdd_free = solve(M, tau_free-C_public-delta_C-G)
a_free = J@qdd_free+b_F
```

This includes the gyro correction; it must not be added a second time. The velocity preprocessing jump is not included in the engine's reported acceleration, so no extra velocity-jump/dt term is added. The native full inertia getter is expressed at COM in the rigid-body-prim frame, so `I_world=R_link @ I_body @ R_link.T`; the COM principal-axis quaternion must not be applied again. [Public FD source](https://github.com/NVIDIA-Omniverse/PhysX/blob/4f2103c3a9052906296defb12166753450ef787c/physx/source/gpuarticulation/src/CUDA/forwardDynamic2.cu#L1259) and [C source](https://github.com/NVIDIA-Omniverse/PhysX/blob/4f2103c3a9052906296defb12166753450ef787c/physx/source/gpuarticulation/src/CUDA/inverseDynamic.cu#L783) support the correction; this public SHA is not established as the exact installed binary's source.

Implicit joint damping and the original legacy friction coefficient are solver terms and remain in this difference. Net contact force remains the input to contact/support diagnostics. It is not substituted for this reward signal.

## Supported physics and reproduction boundary

The validated path has zero explicit body damping and armature, no unaccounted external wrench, and disabled retained acceleration and every-TGS-iteration external-force handling. DOF scaling and gyro truncation are implemented as described above. The initial implementation rejected body speed clamps against reconstructed PRE forward-dynamics velocity. The subsequent source-supported damping extension and its numerical limits are recorded below. POST checks retain finite-value validation but no longer reject a state merely because its speed crossed a PRE source-domain boundary after that step. Source timing requires the pre-state after actual actuator writes and the post-step acceleration report; final endpoint velocity differences are not a substitute for that report.

The first three migration defects found during this work were: rigid-body settings stopped below the nested base, angular-speed limits crossed a rad/s to deg/s interface without conversion, and a new static-friction effort setter had received the old dimensionless friction coefficient. PawCerto now uses official APIs to apply properties to every body, convert the angular limit, and write the actual legacy coefficient. The friction setter is deprecated but exercised on the installed version; support in future versions must be checked explicitly. Later mapping checks also restored the original URDF DOF limits (30.1/20.07 rad/s on leg joints and 10 rad/s on arm joints) and contact/rest offsets (0.01/0 m). A subsequent 4096-environment check exposed the PRE DOF-clamp branch before its first update, motivating the complete correction above. The original Gym inertia-recompute probe supported the existing proportional inertia scaling plus independent COM write, so it did not justify another inertia change.

The [DOF-clamp native check](../outputs/isaac/dof-clamp-free-diagnostic/cpu-production/README.md) now covers unclamped, positive-overspeed and negative-overspeed states under original joint limits, without active solver constraints. CPU float64, CPU float32 and actual CUDA float32 each pass 450/450 acceleration components under the original tolerance. CUDA's maximum error/tolerance is 0.0309. The no-clamp path is bitwise unchanged and 38 CPU tests pass. A subsequent [4096-environment integration](../outputs/isaac/dof-clamp-one-iteration/validation.json) completed 98304 transitions and 256 Adam updates with finite metrics/checkpoint. These results validate the tested DOF correction, not the older high-gyro cases or learned control.

The [high-speed analysis](../outputs/isaac/gyro-clamp-free-diagnostic/cpu-production/README.md) uses three independent 199/201/250 rad/s samples with contacts and joint-position limits excluded in a diagnostic asset. Original mass, inertia, dt and body/DOF speed limits are retained. Actual CUDA has 3/450 components outside the unchanged tolerance, all `link6 angular_z`; all 225 linear components pass. Strong cancellation in those angular sums supports numerical sensitivity but does not establish a unique cause. The full 6D result remains FAIL.

More importantly for EMD, the four-foot CUDA residuals reach approximately 1.8e-4 N in these nominally solver-free diagnostics. Positive residuals make all three inputs choose non-flying, with unweighted penalties about 0.250/0.110/0.022 instead of the ideal-zero penalty 100. A separate [actual original Gym check](../outputs/isaac/original-gym-low-omega-free-diagnostic/summary.json) at 1/5/10 rad/s, with no contact and original DOF limits untriggered, returned all 12 foot Fz exactly zero and all three flying penalties 100. Those are different states and engines, not a high-speed pointwise oracle, but they rule out assuming the original signal necessarily has the same positive near-zero noise. The earlier high-speed Gym samples triggered velocity constraints and are retained as inapplicable to this comparison.

The intended mathematical quantity remains source supported. The numerical consumer limitation is now explicit: small acceleration/force errors alone do not establish original EMD equivalence. Projected joint forces cannot identify exact zero solver activity either; they include actuation and incoming-force contributions without origin labels. A reconstructed-signal learning experiment must retain these limits and cannot be reported as strict sensor or paper-result reproduction.

This limitation also occurs with the current DOF correction: its three actual CUDA solver-free samples have maximum foot-force residuals of approximately 1.53e-7, 1.53e-7 and 7.63e-7 N. The positive-overspeed sample takes the non-flying branch with penalty 0.08614; the other two take the flying branch with penalty 100. Passing the acceleration tolerance does not remove that consumer difference.

The original EMD clipping, normalization, variance, flying branch and reward weight are retained in the integration. Actor/critic inputs remain 132/261 for the published `ours` recipe. New training must identify the reconstructed input and corrected physics in its configuration; historical proxy checkpoints cannot silently resume under changed reward/physics semantics.

The integration iteration took 2.892 seconds, including 2.182 seconds of collection; the whole process took 72.839 seconds including startup and shutdown. The external 0.5-second sampler observed a GPU-process memory peak of 5782 MiB. These are one-iteration measurements, not a sustained-training time guarantee. The preselected learning experiment is described in the [corrected training plan](umi-corrected-training-plan.md).

## Body-speed damping branch exposed by adaptation

The separate relaxed-joint-limit adaptation stopped after 43 completed updates at the body-angular-speed guard; it did not reach its fixed 1000 endpoint. The finite PRE state exceeded the original body speed limit while native joint limits and reconstruction caches remained consistent.

Stock source applies each body speed limit as an additional bias wrench, including root and child links. With full forward-dynamics COM velocity, let `s_linear=max(0,1-vmax/norm(v_F))` and `s_angular=max(0,1-wmax/norm(omega_F))`, using zero for the unexceeded branch. The additional wrench is `[m*v_F*s_linear/dt, I_world@omega_F*s_angular/dt]`; its generalized projection is added to `delta_C`. This does not clip `V_F`, change the kinematic bias, or replace the full angular velocity with its gyro-clipped value. Public C omits this speed-limit term. [Fixed public source](https://github.com/NVIDIA-Omniverse/PhysX/blob/4f2103c3a9052906296defb12166753450ef787c/physx/source/gpuarticulation/src/CUDA/forwardDynamic2.cu#L1295) and the local older source agree on this branch; the exact installed native source SHA remains unknown.

Implementation and bounded current-native checks are complete. Source-aligned multiplication order leaves 10/150 angular components outside tolerance in the linear-speed fixture and 1/150 linear component outside tolerance in the qualified angular fixture. Complete 6D validation remains FAIL; this is not original sensor equivalence. The original failure contains nonzero passive joint damping and friction, so closing contacts alone would not make it a free-dynamics oracle. The qualified linear fixture retains DOF/body limits of 1000. The angular fixture uses diagnostic DOF limits of 1e9, with zero initial joint speed and the original body limit of 1000, to exclude post-step joint-limit solver effects. Two earlier angular fixtures with DOF1000 remain disqualified. The source-order change reduces error but does not pass every component; a same-data Jacobian-geometry variant did not remove failures and was not adopted. Native negative controls without this body term have much larger errors. A separate [bounded adaptation](umi-relaxed-velocity-adaptation.md) proceeds as a reconstructed-signal research experiment with these numerical and EMD limitations, not as a passed sensor-equivalence claim.
