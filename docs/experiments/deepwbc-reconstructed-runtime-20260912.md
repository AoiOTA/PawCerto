# Explicit DeepWBC reconstructed-sensor runtime

This integration makes `reconstructed_sensor_wrench` an explicit training and evaluation choice on official, unmodified Isaac Lab/PhysX. The runtime constructor retains the native joint-reaction default for diagnostics. UMI algorithms and runtime defaults are unchanged. The six-axis reconstruction is approximate: the original short Gym/Lab comparison matched contact bits but contact-scene Fz² MAE was 10–13% of the Gym mean. See [the signal experiment](deepwbc-solver-wrench-20260912.md).

The runtime submits the original explicit PD command at every 5 ms substep, refreshes PRE COM kinematics, reads public M/G/C/J then COM and DOF velocities and actual actuation in native order, and reconstructs free acceleration for all 27 bodies and 20 DOFs. After the physical step it calls `approximate_sensor_wrench` with full reported acceleration and PRE rotation, then selects the four feet. No angular channel is padded with zero. The original environment consumes the fourth 5 ms sample for its 20 ms policy step. Active external wrenches, unsupported model properties, a fixed base or user/backend order mismatch fail explicitly.

Model initialization is lazy so creation randomization has already set native mass, inertia and COM. The creation-randomization owner invalidates this model after writes. Reset clears selected sensor rows while the existing task retains its cloned terminal transition until the next post-physics refresh. Training checkpoints record the chosen force mode and evidence qualification; resume rejects a mode change. An explicit evaluation override is diagnostic and is recorded.

CPU verification covers the runtime PRE/POST order, full-body six-axis output selection, current randomized mass/inertia/COM and gravity, and resume-mode identity. The existing evaluation interface fixture was corrected to contain the evidence field produced by the real `prepare` contract; no production fallback was introduced. The related suite passed 36 tests with 4 standalone-USD skips, and all 4 newly added runtime tests passed after the final ordering check. These interface tests do not establish physical training behavior.

The authorized real run preserves training seed 1, 16 environments and 21 complete public-fresh updates. The fixed evaluation preserves seed 2027, one environment, 500 policy steps (10 s requested), original-play profile, commands `[.5,0,0]`, EE LPY `[.6,-.3,.3]`, trajectory 2 s and hold 1 s. It loads the model-21 export and compares its actions with checkpoint inference on every actual observation. This is a bounded learning-path and policy-consumption exercise, not a learning-success claim. Material/spawn/terrain work remains with the core owner.

The corrected-terrain execution is complete; the final section below records the valid contact-task run and its tracking limitations. Earlier failed and physically invalid attempts remain below with their causes. The fixed task is `outputs/deepwbc-reconstructed-execution-20260912/fixed-task.json`.

## Confirmed terrain-pose cause and fresh retry

The terrain owner confirmed that the old mesh callback interpreted Lab's xyzw identity quaternion as wxyz, producing a 180-degree world-Z rotation. The actual old terrain bounds were X `[-22.475,-7.5]`, Y `[-374.975,-125]`, while all 500 observed robot positions were X `[-3.7084,-2.8107]`, Y `[-95.7731,-94.7749]`: every recorded position was outside the terrain. The corrected complete 19-tile USD bounds are X `[-7.5,7.475]`, Y `[-125,124.975]`, containing all those positions, with corresponding source heights .0419–.14801 m. Evidence: `outputs/deepwbc-terrain/quaternion-repair-20260913/world-result.json`.

This confirms a scene-placement failure, not a policy learning failure. The old 21-update checkpoint and 500-step evaluation are retained as real execution/export evidence from an invalid contact-task placement. They are not accepted as the final learning-path result. With the terrain repair ready, the operator started a fresh seed-1/16-env/21-update run at `outputs/isaac/deepwbc-reconstructed-21updates-terrainfixed-20260913`, preserving the same original algorithm, full geometry, force mode and budget. Its export and fixed evaluation will be checked for actual contact support in addition to finite values and action parity.

Separately, installed-source consumption exposed a CLI identity bug: a `.txt` USD pointer was hashed as text against the saved physical-USD hash. Training and evaluation now resolve the physical USD before hashing or recording its identity. Same-asset pointer aliases pass; changing the physical USD still fails. Fourteen related CPU tests and an actual model-21 pointer preflight passed. This repair does not change the simulation or force formula.
