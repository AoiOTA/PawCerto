# AS2/Piper-H：共同执行语义的下一步选择

1000更新、64例评估及首步限速隔离均已结束。当前没有已验证、保持本轮UMI执行契约且可直接修复迁移失败的代码改动。继续原配方训练不解决已经观察到的执行差异。本页是可审阅的研究选择，不是已运行的新候选，也不增加训练预算。

## 已有证据与不用重复的工作

- 新通用EE策略的首个非零PD请求在两引擎近乎一致；仅将Lab六个Piper速度界从5改为1000 rad/s，就使首步臂响应接近Mu。该20-solve实验已独立复核，见[完整结果](as2-general-ee-learning-result.md#首步速度约束隔离结果)。
- 旧候选已有0.44秒冻结动作限速比较：接触前显著接近，接触后仍分歧。另有5/2.5/1 ms积分细化：速度降低但仍高速，未证明收敛或稳定。相同问题不需再运行，见[既有诊断](as2-umi-migration-next.md#已完成的冻结动作执行器比较)。
- 质量矩阵复算已经解释旧候选首步高速增量；名义小幅关节脉冲可以有限稳定执行。没有发现动作映射、PD符号或首步力矩发送的可修复错误。这些结果不能据此决定新的增益、armature或奖励。

## 三种执行语义的代价

| 选择 | 保留与改变 | 当前用途及缺口 |
|---|---|---|
| 保留Lab外部PD与原生速度约束 | 保留本轮训练的执行契约 | Mu路径尚无经过验证的等价约束实现。事后裁剪qvel不等价；当前只能保留迁移限制。 |
| 两引擎均采用无速度约束的外部PD直接力矩 | 保留动作映射、力矩界、20 ms动作/延迟与5 ms PD时钟；改变Lab训练时的速度约束 | 可明确定义为研究诊断，但已有高速响应，不构成可用控制或物理Piper模型。不能把1000 rad/s写成硬件能力。 |
| 两引擎采用同一有来源的执行器模型 | 保留UMI任务、策略接口及PPO；显式改变机器人执行层 | 面向后续稳定迁移的候选方向。Piper转子/传动等效惯量、摩擦、力矩—速度关系和实际控制周期尚缺可采用依据，不能由URDF的100 Nm/5 rad/s或画册速度反推。 |

积分细化是离散数值选择，不能替代上述执行语义选择。若再次使用微步，原5 ms PD重算与力矩保持时钟应单独记录，不能同时改变控制频率并将效果全部归因于积分。

## 最小所需输入与下一次边界

若走物理执行器路线，首先需要选定实际Piper-H控制模式，并取得该模式下的逐关节力矩限制/速度关系、等效惯量及摩擦依据，或已有位置/速度/电流响应记录。厂商或SDK的可执行模型也可作为来源；若采用仿真假设，必须列出具体数值、依据和未标定项，不能以“真实执行器”命名。

在这些输入或明确的仿真假设形成前，不创建虚假的默认电机参数，不更改已有策略评估，不追加优化器更新。输入齐备后，先将唯一候选写成两引擎可消费的参数与离散更新公式，以同初态、同固定输入、名义/满载两个具名资产的短响应判断是否值得进入固定策略测试。窗口、物理步数、通过/停止条件应随具体候选确定；不能在模型尚未定义时承诺某个短测试已足以验证它。

本页不把缺少硬件标定当作仿真研究的禁令。它指出当前必须明确的是执行模型及假设，不能用更多同类诊断或训练次数代替。默认依赖仍是官方未修改的Isaac Lab/PhysX；硬件执行不在范围内。完整框架、满载稳定控制和跨引擎迁移仍未完成。
